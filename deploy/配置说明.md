# LongPet 刷机后重配置说明

本文用于 LongPet 板卡重新刷写系统后，恢复 LongPet 自启动、Family Link 配置、RTL8188FU Wi-Fi 自愈、LCD VT/控制台抢屏处理等系统配置。

> 本文假定：
>
> - 系统已经正常启动；
> - NetworkManager 正常安装；
> - `longpet` 用户已经由系统镜像创建；
> - `/home/longpet/LongPet` 程序已经部署；
> - 开发电脑可以通过 SSH/SCP 访问板卡。
>
> 当前示例板卡地址：
>
> ```text
> 10.188.219.51
> ```
>
> 如果板卡 IP 发生变化，应替换下面命令中的 IP。

---

# 1. 检查 LongPet 用户和程序目录

板端执行：

```bash
id longpet

ls -ld /home/longpet
ls -l /home/longpet/LongPet
```

正常情况下应该存在：

```text
/home/longpet/LongPet
```

并且程序应该具有可执行权限。

如果没有：

```bash
chmod 0755 /home/longpet/LongPet
```

确保数据库目录存在：

```bash
mkdir -p /home/longpet/data
chown -R longpet:longpet /home/longpet/data
```

## 关于 video/input/audio/tty 用户组
可以：
```bash
awk -F: -v OFS=: '
$1=="video" || $1=="input" || $1=="audio" || $1=="tty" {
    n=split($4,a,",")
    found=0
    for(i=1;i<=n;i++)
        if(a[i]=="longpet") found=1

    if(!found) {
        if($4=="")
            $4="longpet"
        else
            $4=$4",longpet"
    }
}
{print}
' /etc/group > /etc/group.new &&
mv /etc/group.new /etc/group
```
但是当前 `longpet.service` 已配置：

```ini
SupplementaryGroups=video input audio tty
```

因此 **LongPet 通过 systemd 启动时，不要求手工修改 `/etc/group`**。

这比直接使用脚本重写 `/etc/group` 更安全。

只有需要手工切换到 `longpet` 用户运行硬件测试时，才有必要额外持久添加用户组。

# 3. 安装 LongPet 和 Wi-Fi 配置文件

创建目录：

```bash
mkdir -p /usr/local/sbin
mkdir -p /etc/systemd/system/longpet.service.d
mkdir -p /etc/udev/rules.d
```

## 3.1 安装 LongPet systemd service

```bash
install -o root -g root -m 0644 \
    /tmp/longpet.service \
    /etc/systemd/system/longpet.service
```

## 3.2 安装 Family Link 配置

Family Link 文件内包含 Token，因此不要使用 `0644`。

使用：

```bash
install -o root -g root -m 0600 \
    /tmp/longpet-familylink.conf.example \
    /etc/systemd/system/longpet.service.d/familylink.conf
```

编辑：

```bash
vi /etc/systemd/system/longpet.service.d/familylink.conf
```

将：

```text
replace-with-a-random-token
```

替换为实际使用的 Token。

确认权限：

```bash
ls -l /etc/systemd/system/longpet.service.d/familylink.conf
```

应类似：

```text
-rw------- 1 root root ...
```

即：

```text
0600 root:root
```

不要在仍然使用：

```text
replace-with-a-random-token
```

的情况下正式启动 LongPet。

## 3.3 安装 RTL8188FU Wi-Fi 自愈脚本

```bash
install -o root -g root -m 0755 \
    /tmp/rtl8xxxu-wlan0-recover \
    /usr/local/sbin/rtl8xxxu-wlan0-recover
```

## 3.3.1 安装联网 AI 语音配置（启用语音交互时）

先将 `deploy/longpet-ai.ini.example` 上传并改成实际 Gateway、模型和 Token:
```powershell
scp .\deploy\longpet-ai.ini.example root@10.188.219.51:/tmp/
```

再安装：

```bash
install -d -o root -g longpet -m 0750 /etc/longpet
install -o root -g longpet -m 0640 \
    /tmp/longpet-ai.ini.example \
    /etc/longpet/ai.ini
```

`longpet.service` 默认通过
`LONGPET_AI_CONFIG=/etc/longpet/ai.ini` 读取该文件；文件不存在时主程序仍可启动，
但“陪我说话”会提示 AI 配置不完整。

## 3.4 安装 Wi-Fi 自愈 systemd service

```bash
install -o root -g root -m 0644 \
    /tmp/rtl8xxxu-wlan0-recover.service \
    /etc/systemd/system/rtl8xxxu-wlan0-recover.service
```

检查：

```bash
ls -l \
    /etc/systemd/system/longpet.service \
    /etc/systemd/system/longpet.service.d/familylink.conf \
    /usr/local/sbin/rtl8xxxu-wlan0-recover \
    /etc/systemd/system/rtl8xxxu-wlan0-recover.service
```

预期权限大致为：

```text
-rw-r--r--  root root  /etc/systemd/system/longpet.service
-rw-------  root root  /etc/systemd/system/longpet.service.d/familylink.conf
-rwxr-xr-x  root root  /usr/local/sbin/rtl8xxxu-wlan0-recover
-rw-r--r--  root root  /etc/systemd/system/rtl8xxxu-wlan0-recover.service
```

# 4. 配置 LCD VT，解决控制台光标和抢屏问题

LongPet 当前使用：

```text
/dev/fb0
/dev/tty1
```

Qt 配置为：

```ini
QT_QPA_PLATFORM=linuxfb:fb=/dev/fb0:tty=/dev/tty1
```

因此要保证：

1. `/dev/tty1` 对 `tty` 组可读写；
2. `getty@tty0` 不操作 framebuffer console；
3. `getty@tty1` 不和 Qt 抢当前活动 VT；
4. 串口 `ttyS0` 继续作为维护终端使用。

---

## 4.1 创建 tty1 的永久 udev 权限规则

执行：

```bash
cat > /etc/udev/rules.d/70-longpet-vt.rules <<'EOF'
SUBSYSTEM=="tty", KERNEL=="tty1", GROUP="tty", MODE="0660"
EOF
```

重新加载 udev 规则：

```bash
udevadm control --reload-rules
```

当前这次启动立即应用：

```bash
chmod 0660 /dev/tty1
```

检查：

```bash
ls -l /dev/tty1
```

应该类似：

```text
crw-rw---- 1 root tty ... /dev/tty1
```

---

## 4.2 禁止 LCD getty 抢占 VT


Mask tty0：

```bash
systemctl mask getty@tty0.service
systemctl stop getty@tty0.service
```

Mask tty1：

```bash
systemctl mask getty@tty1.service
systemctl stop getty@tty1.service
```

这样 LCD VT 留给 LongPet 使用。

---

## 4.3 保留串口维护终端

不要关闭 `ttyS0`。

执行：

```bash
systemctl unmask serial-getty@ttyS0.service
systemctl enable --now serial-getty@ttyS0.service
```

串口继续用于：

- 内核启动日志；
- root 登录；
- 故障维护；
- LongPet GUI 异常时的恢复操作。

不要删除 bootargs 中：

```text
console=ttyS0,115200
```

检查：

```bash
cat /proc/cmdline
cat /sys/class/tty/console/active
```

执行：

# 6. 重新加载 systemd 并启用服务

完成所有前面的配置后，再统一执行：

```bash
systemctl daemon-reload
```

启用 LongPet：

```bash
systemctl enable longpet.service
```

启用 RTL8188FU Wi-Fi 自愈：

```bash
systemctl enable rtl8xxxu-wlan0-recover.service
```

检查：

```bash
systemctl is-enabled longpet.service
systemctl is-enabled rtl8xxxu-wlan0-recover.service
```

正常应输出：

```text
enabled
enabled
```

---

# 7. 检查 systemd-networkd-wait-online

本系统网络由：

```text
NetworkManager
```

负责。

如果 `systemd-networkd-wait-online.service` 仍处于启用状态，它可能在启动过程中无意义等待约两分钟。

先检查：

```bash
systemctl status systemd-networkd-wait-online.service --no-pager
```

如果确认它仍然启用/运行，而系统只使用 NetworkManager，可以执行：

```bash
systemctl disable --now systemd-networkd-wait-online.service
systemctl mask systemd-networkd-wait-online.service
```

如果本来就是 disabled/masked，则不用处理。

# 8. 第一次启动服务

建议先启动 Wi-Fi 自愈：

```bash
systemctl restart rtl8xxxu-wlan0-recover.service
```

然后启动 LongPet：

```bash
systemctl restart longpet.service
```

检查 LongPet：

```bash
systemctl status longpet.service --no-pager -l
```

查看日志：

```bash
journalctl -b -u longpet.service -n 50 --no-pager
```

不应该再出现：

```text
Failed to open tty (Permission denied)
```

# 9. Wi-Fi 自愈服务状态说明

查看：

```bash
systemctl status rtl8xxxu-wlan0-recover.service --no-pager -l
```

查看日志：

```bash
journalctl -b -u rtl8xxxu-wlan0-recover.service --no-pager
```

## wlan0 已正常存在时

如果当前：

```text
/sys/class/net/wlan0
```

已经存在，服务可能显示：

```text
Active: inactive (dead)
```

并出现：

```text
ConditionPathExists=!/sys/class/net/wlan0 was not met
```

这是 **正常状态，不是错误**。

含义是：

```text
wlan0 已存在
→ 不需要进行 rtl8xxxu 自愈
→ systemd 跳过恢复脚本
```

## wlan0 启动失败时

如果 RTL8188FU probe 失败，没有产生：

```text
wlan0
```

自愈服务才会真正执行恢复脚本。

恢复脚本会等待设备枚举，并尝试重新加载：

```text
rtl8xxxu
```

最多进行有限次数重试。

---

# 10. 重启进行最终持久化验证

所有配置完成后：

```bash
reboot
```

这是必须进行的一步。

因为：

```bash
chmod 0660 /dev/tty1
```

只对当前启动有效。

只有重启以后 `/dev/tty1` 仍然自动变成：

```text
root:tty 0660
```

才能证明：

```text
/etc/udev/rules.d/70-longpet-vt.rules
```

真正生效。

---

# 11. 重启后的完整验收

重新登录板卡后执行：

```bash
echo "===== LONGPET ====="
systemctl is-enabled longpet.service
systemctl status longpet.service --no-pager -l

echo "===== VT ====="
cat /sys/class/tty/tty0/active
ls -l /dev/tty1

echo "===== LCD GETTY ====="
systemctl is-enabled getty@tty0.service
systemctl is-active getty@tty0.service
systemctl is-enabled getty@tty1.service
systemctl is-active getty@tty1.service

echo "===== SERIAL GETTY ====="
systemctl is-enabled serial-getty@ttyS0.service
systemctl is-active serial-getty@ttyS0.service

echo "===== WIFI ====="
ip link show wlan0
nmcli device status
systemctl is-enabled rtl8xxxu-wlan0-recover.service

echo "===== LONGPET LOG ====="
journalctl -b -u longpet.service -n 50 --no-pager

echo "===== WIFI RECOVERY LOG ====="
journalctl -b -u rtl8xxxu-wlan0-recover.service --no-pager
```

# 14. 刷机后配置流程摘要

以后重新刷机，只需要按以下顺序处理：

```text
1. 检查 longpet 用户、程序和 data 目录
                ↓
2. 开发电脑 SCP 上传四个 deploy 文件
                ↓
3. install 到最终系统目录
                ↓
4. 设置 Family Link Token
                ↓
5. 创建 tty1 udev 0660 规则
                ↓
6. mask getty@tty0 / getty@tty1
                ↓
7. 保留 serial-getty@ttyS0
                ↓
8. 检查 longpet.service 不依赖 dev-fb0.device
                ↓
9. daemon-reload
                ↓
10. enable LongPet / Wi-Fi 自愈
                ↓
11. 如有需要禁用 systemd-networkd-wait-online
                ↓
12. 启动服务
                ↓
13. reboot
                ↓
14. 完整验收
```

完成以上步骤后，刷机后的 LongPet 系统配置即恢复完成。

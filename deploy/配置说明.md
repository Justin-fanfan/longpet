# LongPet 刷机后重配置说明

本文用于 LongPet 板卡重新刷写系统后，恢复 LongPet 自启动、Family Link、联网 AI 语音、USB 声卡、RTL8188FU Wi-Fi 自愈、LCD VT/控制台抢屏处理等系统配置。

> 本文假定：
>
> - 系统已经正常启动；
> - NetworkManager 正常安装；
> - `longpet` 用户已经由系统镜像创建；
> - `/home/longpet/LongPet` 程序已经部署；
> - 开发电脑可以通过 SSH/SCP 访问板卡。
> - 启用联网 AI 时，已经在服务商控制台取得可用的 API Key、模型权限和业务空间 ID；
> - 启用 HTTPS 云服务时，系统时间正确且 rootfs 中存在 CA 证书。
>
> 当前示例板卡地址：
>
> ```text
> 10.240.178.51
> ```
>
> 如果板卡 IP 发生变化，应替换下面命令中的 IP。

---

# 1. 检查 LongPet 用户和程序目录

板端执行：

```bash
id longpet

ls -ld /home/longpet
ls -l /home/longpet/LongPet
```

正常情况下应该存在：

```text
/home/longpet/LongPet
```

并且程序应该具有可执行权限。

如果没有：

```bash
chmod 0755 /home/longpet/LongPet
```

确保数据库目录存在：

```bash
mkdir -p /home/longpet/data
chown -R longpet:longpet /home/longpet/data
```

## 关于 video/input/audio/tty 用户组
可以：
```bash
awk -F: -v OFS=: '
$1=="video" || $1=="input" || $1=="audio" || $1=="tty" {
    n=split($4,a,",")
    found=0
    for(i=1;i<=n;i++)
        if(a[i]=="longpet") found=1

    if(!found) {
        if($4=="")
            $4="longpet"
        else
            $4=$4",longpet"
    }
}
{print}
' /etc/group > /etc/group.new &&
mv /etc/group.new /etc/group
```
但是当前 `longpet.service` 已配置：

```ini
SupplementaryGroups=video input audio tty
```

因此 **LongPet 通过 systemd 启动时，不要求手工修改 `/etc/group`**。

这比直接使用脚本重写 `/etc/group` 更安全。

只有需要手工切换到 `longpet` 用户运行硬件测试时，才有必要额外持久添加用户组。

# 3. 安装 LongPet 和 Wi-Fi 配置文件

创建目录：

```bash
mkdir -p /usr/local/sbin
mkdir -p /etc/systemd/system/longpet.service.d
mkdir -p /etc/udev/rules.d
mkdir -p /etc/longpet/
```

## 3.1 安装 LongPet systemd service

```bash
install -o root -g root -m 0644 \
    /tmp/longpet.service \
    /etc/systemd/system/longpet.service
```

## 3.2 安装 Family Link 配置

Family Link 文件内包含 Token，因此不要使用 `0644`。

使用：

```bash
install -o root -g root -m 0600 \
    /tmp/longpet-familylink.conf.example \
    /etc/systemd/system/longpet.service.d/familylink.conf
```

编辑：

```bash
vi /etc/systemd/system/longpet.service.d/familylink.conf
```

将：

```text
replace-with-a-random-token
```

替换为实际使用的 Token。

确认权限：

```bash
ls -l /etc/systemd/system/longpet.service.d/familylink.conf
```

应类似：

```text
-rw------- 1 root root ...
```

即：

```text
0600 root:root
```

不要在仍然使用：

```text
replace-with-a-random-token
```

的情况下正式启动 LongPet。

## 3.3 安装 RTL8188FU Wi-Fi 自愈脚本

```bash
install -o root -g root -m 0755 \
    /tmp/rtl8xxxu-wlan0-recover \
    /usr/local/sbin/rtl8xxxu-wlan0-recover
```

## 3.4 安装联网 AI 语音配置（启用语音交互时）

联网语音链路为：

```text
USB 麦克风录音
    → ASR Provider
    → LLM Provider
    → TTS Provider
    → USB 扬声器播放
```

ASR、LLM、TTS 的 Provider、地址、API Key 和模型彼此独立。即使当前三项都使用阿里云百炼，也不要再写成旧版共用的 `[ai] api_base_url + api_key`。

先在板端复制模板并编辑临时文件：

```bash
cp /tmp/longpet-ai.ini.example /tmp/longpet-ai.ini
chmod 0600 /tmp/longpet-ai.ini
vi /tmp/longpet-ai.ini
```

必须修改：

- 将两处 `{WorkspaceId}` 替换为百炼控制台中的真实业务空间 ID；
- 将三个 `api_key` 替换为对应服务的真实 Key；同一地域和业务空间可以使用同一个 Key，但程序并不要求三者相同；
- 确认模型已在对应地域开通；
- 确认 `voice` 是所选 TTS 模型支持的系统音色；
- 北京、新加坡等地域的 API Key 和域名不能混用。

如果 TTS 改用 `qwen-audio-3.0-tts-flash`，应使用业务空间 API 地址和该模型支持的音色，例如：

```ini
[tts]
provider=aliyun
api_base_url=https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1
api_key=replace-with-bailian-api-key
model=qwen-audio-3.0-tts-flash
voice=longanhuan_v3.6
```

程序会根据阿里云模型系列选择正确的 TTS endpoint；不要把 `/services/...` 的完整接口路径写进 `api_base_url`。

项目中还提供 `deploy/longpet-ai-mixed.ini.example`，用于参考 ASR、LLM、TTS 分别连接不同厂商和不同密钥的配置方式。

### 3.4.2 安装和权限

先确认没有保留模板占位符：

```bash
if grep -Eq 'replace-with|\{WorkspaceId\}' /tmp/longpet-ai.ini; then
    echo "ERROR: AI 配置仍包含占位符"
else
    echo "AI 配置占位符已替换"
fi
```

存在占位符时不要继续正式部署。确认无误后安装：

```bash
install -d -o root -g longpet -m 0750 /etc/longpet
install -o root -g longpet -m 0640 \
    /tmp/longpet-ai.ini \
    /etc/longpet/ai.ini
```

检查非敏感字段可使用：

```bash
grep -E '^\[|^provider=|^api_base_url=|^model=|^language=|^voice=|^request_timeout_ms=|^recording_maximum_ms=|^history_turns=' \
    /etc/longpet/ai.ini
```

`longpet.service` 默认通过：

```ini
Environment="LONGPET_AI_CONFIG=/etc/longpet/ai.ini"
```

读取该文件。文件不存在或字段无效时主程序仍可启动，但“陪我说话”会显示 AI 配置错误。

### 3.4.3 环境变量覆盖（可选）

环境变量优先于 INI，适合临时切换模型或通过 root-only systemd drop-in 注入密钥：

```text
LONGPET_ASR_PROVIDER
LONGPET_ASR_BASE_URL
LONGPET_ASR_API_KEY
LONGPET_ASR_MODEL
LONGPET_ASR_LANGUAGE

LONGPET_LLM_PROVIDER
LONGPET_LLM_BASE_URL
LONGPET_LLM_API_KEY
LONGPET_LLM_MODEL

LONGPET_TTS_PROVIDER
LONGPET_TTS_BASE_URL
LONGPET_TTS_API_KEY
LONGPET_TTS_MODEL
LONGPET_TTS_VOICE

LONGPET_VOICE_SYSTEM_PROMPT
LONGPET_VOICE_REQUEST_TIMEOUT_MS
LONGPET_VOICE_RECORDING_MAXIMUM_MS
LONGPET_VOICE_HISTORY_TURNS
```

一般板端部署优先使用 `/etc/longpet/ai.ini`，避免同时维护两套值。旧 `[ai]` 配置暂时兼容；新旧分组同时存在时，新 `[asr]`、`[llm]`、`[tts]`、`[voice]` 分组优先。

## 3.5 安装天气配置

天气查询使用和风天气（QWeather）「专属 API Host」版本接口，配置独立于 AI 配置，位于 `/etc/longpet/longpet-weather.ini`。


### 3.5.1 填写配置

先在板端复制模板并编辑：

```bash
cp /tmp/longpet-weather.ini.example /tmp/longpet-weather.ini
chmod 0600 /tmp/longpet-weather.ini
vi /tmp/longpet-weather.ini
```

必须替换的字段：

- `api_host`：**你的专属 API Host**，不是共享域名。登录 QWeather 控制台（`https://console.qweather.com`）后，在「设置」页面查看，形如 `abc123xyz.qweatherapi.com`。控制台给的是**不带协议头的裸主机名**，直接照抄即可；程序发现没有 `https://` 前缀会自动补上，两种写都行。模板中的 `https://YOUR_QWEATHER_API_HOST` 仅为占位符，不要直接使用；也不要用 `devapi.qweather.com`；
- `api_key`：和风天气 API Key，通过请求头 `X-QW-Api-Key` 上传，不会出现在 URL 和日志中；
- `latitude` / `longitude`：设备所在地坐标（十进制），第一版不做 GPS/IP 定位，每天固定按此坐标查询。

可选字段：

- `enabled`：`true` 启用，`false`（默认）关闭；
- `language`：`zh` / `en`；
- `refresh_minutes`：状态栏天气刷新周期，默认 30；
- `request_timeout_ms`：单次请求超时，默认 10000；
- `stale_after_minutes`：超过该分钟数后数据标记为过期，默认 120。

确认占位符已替换：

```bash
if grep -Eq 'YOUR_QWEATHER_API_HOST|你的APIKey' /tmp/longpet-weather.ini; then
    echo "ERROR: 天气配置仍包含占位符"
else
    echo "天气占位符已替换"
fi
```

### 3.5.2 安装和权限

```bash
install -d -o root -g longpet -m 0750 /etc/longpet
install -o root -g longpet -m 0640 \
    /tmp/longpet-weather.ini \
    /etc/longpet/longpet-weather.ini
```

`longpet.service` 默认通过：

```ini
Environment="LONGPET_WEATHER_CONFIG=/etc/longpet/longpet-weather.ini"
```

读取该文件。文件不存在、未启用或配置无效时主程序仍可正常启动，状态栏天气保持 `--`。

### 3.5.3 环境变量覆盖（可选）

环境变量优先于 INI：

```text
LONGPET_WEATHER_CONFIG
LONGPET_WEATHER_ENABLED
LONGPET_WEATHER_PROVIDER
LONGPET_WEATHER_API_HOST
LONGPET_WEATHER_API_KEY
LONGPET_WEATHER_LATITUDE
LONGPET_WEATHER_LONGITUDE
LONGPET_WEATHER_LANGUAGE
LONGPET_WEATHER_REFRESH_MINUTES
LONGPET_WEATHER_REQUEST_TIMEOUT_MS

```

日志只输出 provider / 错误码 / HTTP 状态 / 响应 code，不会输出 API Key。

# 4. 配置 LCD VT，解决控制台光标和抢屏问题

LongPet 当前使用：

```text
/dev/fb0
/dev/tty1
```

Qt 配置为：

```ini
QT_QPA_PLATFORM=linuxfb:fb=/dev/fb0:tty=/dev/tty1
```

因此要保证：

1. `/dev/tty1` 对 `tty` 组可读写；
2. `getty@tty0` 不操作 framebuffer console；
3. `getty@tty1` 不和 Qt 抢当前活动 VT；
4. 串口 `ttyS0` 继续作为维护终端使用。

---

## 4.1 创建 tty1 的永久 udev 权限规则

执行：

```bash
cat > /etc/udev/rules.d/70-longpet-vt.rules <<'EOF'
SUBSYSTEM=="tty", KERNEL=="tty1", GROUP="tty", MODE="0660"
EOF
```

重新加载 udev 规则：

```bash
udevadm control --reload-rules
```

当前这次启动立即应用：

```bash
chmod 0660 /dev/tty1
```

检查：

```bash
ls -l /dev/tty1
```

应该类似：

```text
crw-rw---- 1 root tty ... /dev/tty1
```

---

## 4.2 禁止 LCD getty 抢占 VT


Mask tty0：

```bash
systemctl mask getty@tty0.service
systemctl stop getty@tty0.service
```

Mask tty1：

```bash
systemctl mask getty@tty1.service
systemctl stop getty@tty1.service
```

这样 LCD VT 留给 LongPet 使用。

---

## 4.3 保留串口维护终端

不要关闭 `ttyS0`。

执行：

```bash
systemctl unmask serial-getty@ttyS0.service
systemctl enable --now serial-getty@ttyS0.service
```

串口继续用于：

- 内核启动日志；
- root 登录；
- 故障维护；
- LongPet GUI 异常时的恢复操作。

不要删除 bootargs 中：

```text
console=ttyS0,115200
```

检查：

```bash
cat /proc/cmdline
cat /sys/class/tty/console/active
```

# 5. 检查 longpet.service 的关键配置

执行：

```bash
cat /etc/systemd/system/longpet.service
```

至少确认存在：

```ini
User=longpet
Group=longpet
SupplementaryGroups=video input audio tty
```

以及：

```ini
Environment="QT_QPA_PLATFORM=linuxfb:fb=/dev/fb0:tty=/dev/tty1"
```

联网 AI 和 USB 声卡还应确认：

```ini
Environment="LONGPET_AI_CONFIG=/etc/longpet/ai.ini"
Environment="LONGPET_AI_CAPTURE_DEVICE=plughw:CARD=Device,DEV=0"
Environment="LONGPET_AI_PLAYBACK_DEVICE=plughw:CARD=Device,DEV=0"
```

启用天气查询时还应确认：

```ini
Environment="LONGPET_WEATHER_CONFIG=/etc/longpet/longpet-weather.ini"
```

这里的 `CARD=Device` 来自当前 USB 声卡。重刷系统或更换声卡后先执行：

```bash
cat /proc/asound/cards
arecord -L
aplay -L
```

如果 USB 声卡名称发生变化，需要同步修改 `longpet.service` 中的录音和播放设备。不要重新指向已经拆除的板载 ES8388。

检查服务文件是否含有异常的 Windows CRLF 字符：

```bash
sed -n '1,120l' /etc/systemd/system/longpet.service
```

如果每行末尾出现可见的 `\r$`，应先转换为 Unix LF 后再 `daemon-reload`。

# 7. 检查 systemd-networkd-wait-online

本系统网络由：

```text
NetworkManager
```

负责。

如果 `systemd-networkd-wait-online.service` 仍处于启用状态，它可能在启动过程中无意义等待约两分钟。

先检查：

```bash
systemctl status systemd-networkd-wait-online.service --no-pager
```

如果确认它仍然启用/运行，而系统只使用 NetworkManager，可以执行：

```bash
systemctl disable --now systemd-networkd-wait-online.service
systemctl mask systemd-networkd-wait-online.service
```

如果本来就是 disabled/masked，则不用处理。

# 8. 第一次启动服务

启用百炼等 HTTPS 云服务时，启动前先检查系统时间和 CA 证书：

```bash
date
test -r /etc/ssl/certs/ca-certificates.crt && echo "CA certificate bundle: OK"
```

系统时间明显错误会导致 TLS 证书校验失败。没有 CA 证书时应先补入 rootfs，不要通过关闭 TLS 校验绕过。

建议先启动 Wi-Fi 自愈：

```bash
systemctl restart rtl8xxxu-wlan0-recover.service
```

然后启动 LongPet：

```bash
systemctl restart longpet.service
```

检查 LongPet：

```bash
systemctl status longpet.service --no-pager -l
```

查看日志：

```bash
journalctl -b -u longpet.service -n 50 --no-pager
```

AI Provider 配置加载正常时，日志中应能看到类似：

```text
AI ASR provider: aliyun
AI LLM provider: openai-compatible
AI TTS provider: aliyun
```

日志不应输出完整 API Key。

天气配置正常且启用时，日志中应能看到：

```text
Weather service starting, provider= qweather refresh_minutes= 30
Weather updated: 多云 24° observedAt=
```

离线状态会出现：

```text
Weather refresh skipped: network unavailable
```

天气日志同样不会输出 API Key。未启用天气时日志为：

```text
Weather disabled; weather service not started
```

不应该再出现：

```text
Failed to open tty (Permission denied)
```

# 9. Wi-Fi 自愈服务状态说明

查看：

```bash
systemctl status rtl8xxxu-wlan0-recover.service --no-pager -l
```

查看日志：

```bash
journalctl -b -u rtl8xxxu-wlan0-recover.service --no-pager
```

## wlan0 已正常存在时

如果当前：

```text
/sys/class/net/wlan0
```

已经存在，服务可能显示：

```text
Active: inactive (dead)
```

并出现：

```text
ConditionPathExists=!/sys/class/net/wlan0 was not met
```

这是 **正常状态，不是错误**。

含义是：

```text
wlan0 已存在
→ 不需要进行 rtl8xxxu 自愈
→ systemd 跳过恢复脚本
```

## wlan0 启动失败时

如果 RTL8188FU probe 失败，没有产生：

```text
wlan0
```

自愈服务才会真正执行恢复脚本。

恢复脚本会等待设备枚举，并尝试重新加载：

```text
rtl8xxxu
```

最多进行有限次数重试。

# 10. 重启进行最终持久化验证

所有配置完成后：

```bash
reboot
```

这是必须进行的一步。

因为：

```bash
chmod 0660 /dev/tty1
```

只对当前启动有效。

只有重启以后 `/dev/tty1` 仍然自动变成：

```text
root:tty 0660
```

才能证明：

```text
/etc/udev/rules.d/70-longpet-vt.rules
```

真正生效。

---

# 11. 重启后的完整验收

重新登录板卡后执行：

```bash
echo "===== LONGPET ====="
systemctl is-enabled longpet.service
systemctl status longpet.service --no-pager -l

echo "===== VT ====="
cat /sys/class/tty/tty0/active
ls -l /dev/tty1

echo "===== LCD GETTY ====="
systemctl is-enabled getty@tty0.service
```

# 15. 联网 AI 常见问题

## 15.1 提示配置不完整或 Provider 不受支持

只检查非敏感字段：

```bash
grep -E '^\[|^provider=|^api_base_url=|^model=|^language=|^voice=' \
    /etc/longpet/ai.ini
```

当前支持的名称：

```text
ASR: aliyun, dashscope, openai-compatible, openai
LLM: openai-compatible, openai, aliyun, dashscope
TTS: aliyun, dashscope, openai-compatible, openai
```

使用 `provider=aliyun` 的 LLM 时，`api_base_url` 仍须填写百炼的 `compatible-mode/v1` 地址；通常直接写 `provider=openai-compatible` 更清楚。

## 15.2 鉴权失败（Unauthorized / HTTP 401 / 403）

依次确认：

1. API Key 没有多余空格或引号；
2. API Key 属于当前配置的地域和业务空间；
3. 模型已经开通且当前账号有调用权限；
4. ASR、LLM、TTS 没有误用另一套 Key；
5. 修改配置后已经执行 `systemctl restart longpet.service`。


## 15.3 HTTP 404、模型不存在或返回格式异常

检查 `api_base_url`：

- 百炼 ASR 通常以 `/api/v1` 结尾；
- 百炼 OpenAI-compatible LLM 以 `/compatible-mode/v1` 结尾；
- `qwen3-tts-*` 示例以 `https://dashscope.aliyuncs.com/api/v1` 为 Base URL；
- Base URL 后不要手工追加 `chat/completions`、`services/aigc/...` 或 `SpeechSynthesizer`，这些路径由对应 Provider 添加。

再检查模型名和 TTS voice 是否匹配。模型系列不同，允许的音色和接口也不同。

## 15.4 网络错误、DNS 错误或请求超时

```bash
nmcli device status
ip address show wlan0
ip route
date
test -r /etc/ssl/certs/ca-certificates.crt && echo CA_OK
journalctl -b -u longpet.service -n 100 --no-pager
```

重点检查：

- wlan0 是否已连接；
- 是否存在默认路由；
- 系统时间是否明显错误；
- rootfs 是否有 CA 证书；
- 配置的域名和地域是否正确；
- `request_timeout_ms` 是否过小。

## 15.5 ASR 没有声音或 TTS 无法播放

先停止 LongPet，避免 ALSA 设备占用，再做回环录放测试：

```bash
systemctl stop longpet.service
timeout 5 arecord \
    -D plughw:CARD=Device,DEV=0 \
    -f S16_LE -r 16000 -c 1 \
    /tmp/longpet-mic-test.wav
aplay -D plughw:CARD=Device,DEV=0 /tmp/longpet-mic-test.wav
systemctl start longpet.service
```

如果设备名不是 `Device`，以 `cat /proc/asound/cards`、`arecord -L` 和 `aplay -L` 的实际结果为准，并同步修改 `longpet.service`。

检查 GStreamer 音频组件：

```bash
gst-inspect-1.0 alsasrc
gst-inspect-1.0 alsasink
gst-inspect-1.0 decodebin
gst-inspect-1.0 audioconvert
gst-inspect-1.0 audioresample
```

## 15.6 天气常见问题

### 状态栏天气一直显示 `--`

依次检查：

1. `enabled=true` 是否写入 `/etc/longpet/longpet-weather.ini`；
2. `api_host` 是否为控制台「设置」中的**专属 API Host**（`devapi.qweather.com` 旧共享域名不可用）；
3. `api_key` 是否有效、无多余空格；
4. 日志中 `Weather update failed` 的错误码：
   - `Unauthorized`：Key 无效或该 Key 的 Host 不匹配；
   - `RateLimited`：请求频率超过配额，减少 `refresh_minutes`；
   - `ConfigurationError`：Host / 参数错误，重点检查 `api_host` 是否填成了别家的 URL；
   - `ServerError`：服务端异常，稍后重试即可；
   - `InvalidResponse` 且诊断含 `missing now.temp`：固件为旧版本（旧解析只认字符串字段）。新版 `/weather/v1/current` 的 `temp/feelsLike/humidity` 是 JSON 数字，旧固件解析不了，需升级到本修正后的版本；现场可先验证接口本身：
     `curl -sS -H "X-QW-Api-Key: <你的Key>" "https://<专属Host>/weather/v1/current/<纬度>/<经度>"`
5. 离线时只会出现 `Weather refresh skipped`，请先确认 wlan0 联网。

### 状态栏一直 `--`，日志只有一条 "Weather refresh skipped: network unavailable"

- 这是**启动竞态**：板子开机时 wlan0 尚未连上，应用启动即刷被"离线"跳过；
- 旧版本此后要等 `refresh_minutes`（默认 30 分钟）才再尝试，短时间观察自然"没有天气"；
- 新版本会在**网络变为可用时立即补刷**（wlan0 连上几秒内出天气），连续离线判定 3 次还会
  强行探测一次；若仍无天气，请按上一节排查错误码；
- 若开机很久后状态栏仍显示 `网络状态未知`（而不是 网络正常/未连接），说明板子系统队列
  `QNetworkInformation` 插件/NetworkManager 未就绪，可先在板上直连验证 API（见上一节 curl）。

### 日志出现 `Protocol "" is unknown`

- 这是 `api_host` 缺少协议头（如 `ph6vhhujph.re.qweatherapi.com`，控制台「设置」给的形式），
  旧固件不会补 `https://`，请求发不出去；
- 新版固件会自动补 `https://`，无需改配置；若用旧固件，把配置改成
  `api_host=https://ph6vhhujph.re.qweatherapi.com` 即可先验证。

### 状态栏只有文字、没有天气图标

- 说明天气数据本身已成功获取（有温度显示），仅缺图标：`icon` 编码为空或不在映射表中（如新扩展编码），纯文本展示是预期行为；
- 若期望图标出现，把该编码补充到 `weatherIconResource` 映射表即可。

### 注意

- 日志与 UI 均不展示 API Key；
- 不配置天气或配置错误都不会影响 AI、Family Link、视频通话等既有功能；
- 和风使用条款要求的来源署名（`天气数据：和风天气 (QWeather)`）在设置页「关于设备」副标题，状态栏只显示图标 + 温度（紧凑样式）。
